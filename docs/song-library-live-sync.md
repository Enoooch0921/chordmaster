# 團隊歌曲庫即時更新與編輯狀態

歌曲儲存後使用既有 `songs` Postgres Changes 通知，250ms 合併通知後讀回目前歌曲庫。每 15 秒以歌曲 ID 與更新時間檢查漏失事件，只在版本改變時讀回完整譜面；返回前景和重新連線亦會補讀。

同步不重新載入頁面、不更換目前歌曲、不重建編輯器。沒有變更的歌曲、歌單及專案保留原物件參照，避免影響無關譜面及編輯歷史。以預覽直接編輯為主要流程：點選小節／段落的快捷編輯，或直接編輯標題、速度與歌曲資訊，從開啟到關閉都顯示編輯狀態並暫緩套用遠端更新，包含尚未改字的輸入框及仍留在欄位內的草稿。相同保護也用於共享歌單的預覽資訊編輯。傳統編輯器、曲庫管理、演出模式、未儲存修改或正在寫入時亦暫緩套用；結束後再補同步。編輯狀態與錯誤訊息使用固定高度，避免通知推動列表或譜面。

正在編輯的歌曲以私有 `song-editors:<libraryId>` Presence 頻道傳送使用者顯示名稱、歌曲 ID、工作階段 ID 和時間，不傳譜面、電子郵件或憑證。歌曲列表和目前歌曲顯示其他工作階段的編輯者；這是提示，不是鎖定或多人文字合併。同帳號其他裝置仍可顯示。停止編輯、切換曲庫、離開前景或斷線後移除；20 秒心跳、75 秒過期檢查避免殘留提示，單純心跳不引起畫面更新。

NAS 須套用 `supabase/migrations/20261026082701_song_editing_presence.sql`。讀取限歌曲庫成員；發布限有歌曲編輯權限者；不更改現有歌曲權限，不開放公開 Presence。2026-10-26 已在 NAS 備份既有 policies、回滾試跑、套用並確認 RLS 與 authenticated-only policies。

測試涵蓋歌曲通知合併、15 秒版本補讀、新增／編輯／封存／刪除、編輯期間暫緩與競態、工作階段清理、斷線恢復、同帳號多裝置、失效提示及焦點保留。雙本機分頁使用實際 SongEditor 與同步 hook、模擬遠端通知，確認捲動、焦點、游標與未儲存段落文字保持不變。另以實際 App 的預覽點選流程測試小節、標題、速度，確認尚未改動儲存資料時便開始保護、取消後結束編輯狀態，前景切換和重新渲染保留欄位草稿與選取位置。證據在 `src/App.previewCollaboration.test.tsx` 及 `tmp/song-live-sync-20261026/`。

前端尚未發布；正式 NAS 的已登入雙帳號 WebSocket 實測尚未執行。直接使用私密金鑰產生登入憑證的探測方案被自動安全審核拒絕，未執行；正式連線驗證須使用一般登入流程。
