# TopChurchWorship 轉錄規則

## 版本與翻譯署名

- **歌名不重複歌手／團隊（2026-10-23 使用者補充）：** 已有專用欄位的歌手、樂團、團隊／版本來源不再重複塞入歌名；只保留曲名、辨識實際編曲所需的版本差異／來源編號及校對狀態。移出歌名的署名須先確認專用欄位已完整保留，不刪來源證據。SOP 與「讚美之泉」是同一名稱，署名統一用「讚美之泉」，不並列重複；人名、譯者與不同版本不可只因相似而合併。

- 原譜或已核對同曲詞版有明確出處，填入現有「版本」欄位（目前儲存於 `lyricist`；舊 `composer` 也會參與版本顯示）。不要把團隊／歌手當作已確認作詞者。
- 原稿明確署名翻譯者才填 `translator`，無署名留空，不從中文譯文猜譯者。
- 有既有非空值、不同詞版／編曲出處、疑似拼字錯誤或歌本編號時，保留並列待核。不能全域覆蓋，也不因同名直接配版本。
- 版本盡量簡潔，例如「讚美之泉」；專輯名與完整原始署名保存在來源紀錄。

## 段落標題與聲部

- 標題盡量只留 Intro、Verse 1、Chorus、Bridge 等段名及必要編號。具意義的 Verse 1／2 等共用編號保留。
- 破折號、斜線或空白後的 EG solo、Build、回 Verse、再現／待校等演奏提示也移到首小節，不只處理括號。Down／Drop 等編曲強弱提示不占段名；共用段、房子編號與組曲中辨識歌曲所需的名稱保留。
- **BreakDown 可作段落標籤（2026-10-23 使用者補充）：** BreakDown／Breakdown 可以直接作為有實際音樂內容的段落標題，不再一律移到首小節註記。保留使用者最新 NAS 的段落分法；不是每個格內 Breakdown 提示都要另拆新段，也不建立空白段落。
- 原標題的調性、反覆、房子、配位待校、樂器／編曲等提示移至首小節註記或聲部標籤，不刪掉資訊。段落本身 `keyChangeTo`、小節數及導航均保留。
- 同一段連續 EG、Pno 等聲部僅在開始標一次；換聲部、新段落才再標。不要逐小節重印 EG。
- **房子不另造重複段標（2026-10-22 使用者補充）：** 同一 Pre-Chorus 等樂段的第一、第二房，保留在同一樂段，以房號表達分支；不要為第二房再建立同名段落標籤。合併時保留全部實際小節、原小節 ID、房號、反覆與必要弱起提示。
- **原曲說明不等於本譜樂段（2026-10-22 使用者補充）：** 頁首提及原曲另有 Bridge，卻未提供本編曲的 Bridge 和聲／小節時，不據此建立空白 Bridge 標籤或假小節。〈勝過這世界〉這類頁首說明保存在來源／外部審核紀錄；本譜只列有實際音樂內容的樂段。
- **未署樂器不加泛稱標籤（2026-10-22 使用者補充）：** 原稿沒有明確指定樂器／聲部時，`label`、`riffLabel`、`rhythmLabel` 留空，不自行補「器樂」「樂器」「伴奏」等泛稱。只有 Intro、Interlude、Instrumental 等段名，不代表已指定樂器；段名及有來源的旋律、節奏照留。原稿明寫 Synth Lead、Pno、EG、Unison 等樂器／聲部／演奏標示才照錄。〈聖靈的火〉Intro 的自加「器樂」標籤須移除；既有歌曲後續依來源簡查時一併處理同類標籤，不用全域關鍵字盲刪。
- **依聲部而非段名判斷旋律（2026-10-22 使用者更正）：** 不新增人聲演唱旋律的簡譜；但原稿明寫的器樂填句、Voicing、Bass 等有音高聲部，即使位於 Verse、Chorus、Tag 等人聲段，也須照音高轉成 `riff`／`riffVoices`，不能降成只有 `rhythm`／`rhythmVoices` 的節奏，或只把音高藏在註記。前奏、間奏及其他段落同樣依來源處理。上下聲部須分開保存；保留原時值、休止、八度記號與未定空位，不從樂器名稱猜八度。此條覆蓋先前「只在前奏、間奏才加旋律」的過度限制。
- **有音高、時值未明的片段：** 不為填入 `riff` 而猜定四分音符、落拍或小節歸屬。先以簡短演奏提示／具體「待檢查：」保留原音高順序，附原稿定位；記錄未定時值旋律的表示需求。有完整音高與時值依據的片段（如 Every Praise 的填句與雙聲部）仍必須轉為旋律聲部，不能以此為由保留錯誤的純節奏。
- 雙語詞以原始句配對，左右共用列高及整對分頁；畫面折行不是新唱句。中文繁體，無原文不生成翻譯。
- **歌詞保留基本段落、不隨演出重複展開（2026-10-23 使用者以〈I Speak Jesus〉歌詞 PDF 補充）：** 依歌詞檔本身的 Verse 1／2／3、Chorus、Bridge 等基本段落整理，中英逐句配對；相同歌詞段落只收一次，不因和弦譜有 Chorus 1／2、Bridge 1／2、Up、房子或反覆就複製歌詞。實際不同的詞句及主歌編號仍保留，不把不同段落誤刪為重複。來源只有編號／※／◎時可對應基本段名，演出導航留在樂譜。範例來源為 Drive `1xDzuJuOEVZeSHFOS626Ct7zc9A9y1ky8`；其兩頁的左右／上下雙語格式共用相同基本段落，本條先約束內容結構，保留 App 目前的顯示偏好。已人工確認的歌曲僅作參考，不因本條擅自改寫。

## 更新安全

**急用歌曲先按原調（2026-10-23 使用者補充）：** 校對先依原譜與原調進行。歌單旁提出的 D 等演出調先記錄需求；本輪不預先改變歌曲顯示調性。使用者另行要求實際切換時，再用既有轉調功能處理；原調與原始和弦/音高仍須完整保存。

**〈讚美你到永遠〉暫定演出編排（2026-10-23 使用者指定）：** 本曲先採每個和弦四拍／一小節；Bridge 結束回 Chorus 前，再加一小節 C（四拍），保留原調 G。這是使用者指定的暫定編排，不能聲稱原稿已印這些落拍，也不類推到其他未分小節歌曲。原始和弦行序與缺少小節線的來源證據留在 audit，譜面只標必要的「回 Chorus」提示。

**後續 NAS 編輯優先：** 最新 NAS 已刪除上方新增的 Bridge 額外 C 格，並改為「讚美你到永遠（待人工）」及新的版本／排版欄位。本次回讀驗證保留該最新 49 格（Bridge 9 格）、每和弦四拍與原調 G，不因上方較早的 50 格紀錄自動補回額外 C。完整證據為 `tmp/topchurch-conversion/delivery/review-session-20261022/2180-plan.json` 與 `2180-verification.json`。

只修改 TopChurchWorship 指定既有歌曲，寫入前備份並以完整舊 JSON 保護，更新後逐首回讀。不得整庫替換，不改個人庫或其他團隊。原稿未知欄位須保持待校，不為清除警告猜填。

**使用者補交缺少歌曲的原譜（2026-10-23）：** 使用者為已指定的急用歌曲補交完整原譜，而 NAS 確認無該曲時，可在 TopChurchWorship 新增該首。先備份全部現有列並檢查同名／同 ID，使用單筆 insert，不以 upsert 覆蓋；完整回讀新歌並逐列確認原有歌曲未變。原始 623 首的歷史完成數保留，新增歌曲明列為範圍增補，同步目前清單、校對進度與來源證據。

## 譜面註記：只保留演奏資訊與具體疑點（2026-10-22）

- **情緒與氛圍描述不放譜面（2026-10-23 使用者補充）：** 「喜樂、讚美地」「敬拜地、感恩地」「喜悅地、單純地」「傾心敬拜地、信心地」等情緒／氛圍文字，即使原譜有印，也只保存在來源審核紀錄，不另加在譜面註記。此條適用後續校對及本輪已簡查的歌曲；混合註記僅移除這類文字，具體拍位、弱起、導航、樂器與力度／漸強漸弱等可執行資訊依原稿處理。

依使用者要求，後續校對同時整理本次涉及的註記，不再把校對過程寫入譜面。原有「資訊不可刪除」指來源證據須留存，不表示每段歷史說明都要顯示在小節上。

- 保留會影響演奏的簡短提示，例如「EG solo」「第二遍進 Chorus」「A/C# 提前半拍（前格 4&）」；已有箭頭、反覆或房子等正式記號時，避免再用文字重複，除非文字補充必要時值或條件。
- **短標籤結尾不加句號（2026-10-23 使用者補充）：** 「AG 8 beats」「8 beat build」「Up」「Breakdown」這類簡短樂器／演奏標籤不加結尾句號（包含「。」與英文句點）。不要改動原有數字、縮寫內部標點、音樂內容或具體待檢查問題；一般完整句子不在本條刪除範圍。
- 未解決的疑點一律以 `待檢查：` 開頭，說明「哪裡、什麼不確定、需要確認什麼」。就近標在相關小節；全曲共通問題只標一次。不要只寫「待校」「待核」「拍位待確認」。不確定仍保留，不為消除文字猜填內容。
- **歌詞問題另外記錄（2026-10-22 使用者補充）：** 缺歌詞、詞句版本、翻譯、唱句配位及回唱歌詞等疑點，另存獨立歌詞待辦清單，附歌曲 ID、來源與具體問題，不放進樂譜的註記或「待檢查」。本輪清單為 `tmp/topchurch-conversion/delivery/review-session-20261022/lyric-review-items.json`／`.md`。若與和聲、節奏或導航混合，先拆開：音樂疑點留譜，歌詞疑點另存。必要的演奏入口提示（例如某字弱起進 Chorus）仍可保留，不能把實用入口指示一併刪掉。
- 例：「待檢查：原稿未註拍號，請確認全曲拍號。」「待檢查：此格第二個和絃的落拍不明。」「待檢查：Bridge 末尾缺少 Coda 目標段。」「待檢查：低音字形可能為 B 或 Bb，需較清晰原稿。」
- 移出譜面的內容包括：第幾批、dpi／SHA／JSON、測試與備份結果、核對經過、「本次確認」「按原樣保留」「沒有自行補入」「不因常用版本改譜」等自述，以及已由欄位或標題表達的調性、速度、完成狀態摘要。依據與修改前全文保存在批次 audit，譜面不重印。
- 混合註記要拆開：保留演奏資訊，疑點改寫為 `待檢查：…`，其餘移入 audit。不可用關鍵字或長度直接整段刪除；長註記可能是未分小節來源的唯一和絃順序、歌詞配位或版本差異紀錄，必須先確認內容已由其他結構完整承載。
- 一個問題以一句為原則，不重述已知事實；必要資訊優先於字數限制。不修改來源原文中的指示，不擅自清空使用者新增的註記。新檢查點要保留本規則的文件路徑。

## 跨小節和絃提前：優先使用搶拍箭頭（2026-10-22）

### 原稿明寫的數拍斜線（2026-10-22 使用者補充）

- **整格單一和弦的排版例外（2026-10-23 使用者最新補充）：** 像〈主的喜樂是我力量〉前奏，整小節只持續同一和弦，逐拍 `/` 使和弦旁擁擠時，省略這些純數拍斜線；後續整格延續同一和弦亦可留空。保留原小節數、真正換和弦的拍位及反覆記號，原譜斜線另存來源紀錄。此例外優先於下方逐一保留原稿斜線的舊要求；不刪 `C / / G/B`、`Csus4 C / /` 這類同格多次換和弦所需的數拍提示，不動斜線低音、休止、獨立節奏或 `%` 小節反覆。

- 原譜明確寫 `C / / G/B` 時，四個拍槽依原稿保存為 `['C','/','/','G/B']`，不能把數拍斜線 `/` 全改成空字串。G/B 的斜線低音須完整保留，不拆成數拍符號。
- 只補有來源依據的斜線；不把空白、未定拍位或長音自動補成 `/`。以拍格與原稿逐一核對，加入符號後確認實際換和弦落拍不變。
- **已確認第1／4拍的延續（2026-10-22 使用者補充）：** 原稿或使用者明確確認和絃在第1、4拍換入，且第2、3拍持續前一和絃、沒有休止或其他事件時，即使未逐一寫斜線，也補成 `['C','/','/','G/B']`。不能從兩個和絃的字距或舊暫排位置推定落拍；未定拍位不套用。本條補充上方「只補原稿明寫斜線」的範圍，已確認的持續拍亦可依此補齊。
- **已確認第1／2拍的延續（2026-10-22 使用者再補充）：** 和絃在第1、2拍換入，且第3、4拍持續第二個和絃、沒有休止或其他事件時，補成 `['Csus4','C','/','/']`；同樣需要已確認的落拍，不能從字距或未定拍位猜填。第1／4拍與第1／2拍兩種情況都納入後續逐首校對及待人工譜面的簡查。
- **同一行的和絃與休止：** 原稿若如〈Same God〉Verse 1／Verse 3／4 結尾，僅同列「F、四分休止、二分休止」，應以和絃拍格 `['F','0','0h','']` 表示；二分休止覆蓋第3、4拍。不要另造一行四分擊奏與重複休止；這不授權刪除原稿確有的獨立節奏聲部。休止拍不能補成和絃延續 `/`。
- 先前已轉待人工但漏存明確數拍斜線的歌曲，也納入後續新規則簡查；只針對此項查原稿，不因此重做無新證據的其他疑點。

### 搶拍箭頭

- 使用者已在〈不動搖的信心〉確認：前一格末端出現的和絃若只是下一格同和絃的提前進入，優先在**下一格的該和絃上方標左向箭頭**，移除前一格代表同一次換和絃的重複項目與多餘落拍標籤。不要移除前格其他獨立和絃、節奏、人聲或器樂音符。
- **下一格原為空白延續亦適用（2026-10-22 使用者以〈勝過這世界〉補充）：** 確認原格末和絃是提前進入下一格並持續時，下一格即使原本未重印該和絃，也應將該次和絃移至下一格並加左箭頭；清除原格該事件與失效 offset，不再以原格末的 4& 標籤代替。只轉換已由來源／使用者確認的跨格提前；格內獨立的 3& 等事件及人聲弱起提示保留。原稿明確的提前量存於 audit，演奏需用時簡短共註一次，不能由箭頭推定未確認的半拍。
- 例：`G … D/F#（4&） | D/F#` 可表達為 `G | D/F#〈左向搶拍箭頭〉`。來源已確認的 4&／提前半拍必須留在來源審核紀錄；演奏需要時可於段首簡短標一次，不逐格重複說明。
- **箭頭本身只表示提前，並不指定提前半拍。** 只有來源或使用者明確確認的時值才能標為 4&。〈不動搖的信心〉後來指定的 G/B→D/A、Em→A 共四處只確認改用提前箭頭，沒有確認精確落拍；不能由其他位置類推半拍。
- 只在來源／使用者已確認為同一次提前進入時合併；相鄰同名和絃可能是再次彈奏、反覆邊界或不同遍版本，不能靠字串相同全域轉換。未確認是否提前時，保留資料，標「待檢查：此處是否提前進入下一小節和絃？」；已由使用者確認的問題則移除，不重貼舊待確認文字。
- 儲存須依 `docs/chord-timing-format.md`：`chordTimingVersion: 2` 的 `<` 表示提前／左箭頭，`>` 表示延後／右箭頭；符號是儲存語法，畫面應使用現有箭頭元件。舊格式先使用既有 migration，不能把舊版符號直接當新版解讀，或只改版本號導致其他箭頭反向。

## 校對效率與停止重複工作（2026-10-22）

- **先分流再目視。** 每次只讀精簡檢查點、當前候選歌曲與必要規則；完整清單交由程式比對，只輸出差異與統計，不把整庫 JSON、完整工具紀錄或歷史報告倒入對話。
- **有新證據才重查。** 將歌曲分成可修正、等待人工／原稿、目前來源已核完。無法確認的問題記錄來源檔 SHA、歌曲內容 SHA、具體疑點及重新開啟條件，例如新原稿、新版本證據、使用者確認或相關表示能力修復。沒有相關變化就略過；有實質變更時先做差異檢查，再決定重查範圍。
- **每首先看整頁，疑點才放大。** 重用已核對且 SHA 相同的來源及影像。只有整頁無法辨識的局部才新增裁切，不預先為每首產生大量高解析影像，不重複檢查與本次問題無關的頁面。
- **共用執行器，小批處理。** 逐步使用共用讀取、差異白名單、驗證與寫入流程，避免每首複製一套長腳本。同類低風險註記整理可每批約 5–10 首；音符與導航複雜者縮小批次。批次大小不是完成量，不能為湊數或耗額度猜填。
- **保留安全檢查，減少重複傳輸。** 每個寫入批次保留完整 NAS 現有列備份與批後全庫比對；同批共用前後快照，逐首仍須完整 JSON 比對、即時併發檢查、條件更新及完整回讀。未寫入時不反覆做全庫掃描。最新 NAS 與本機不同時先保留人工編輯，不能用舊清單覆蓋。
- **按變更驗證。** 純註記整理驗證允許欄位、原音樂資料完全不變及實際使用的註記顯示；不每首跑整套 app 測試、建置與四種轉調。音符、和絃、時值、導航或顯示能力變更才做相應驗證。共用驗證可在相同程式雜湊及相同適用範圍下重用；程式已改時不得沿用舊通過結果。
- **紀錄寫一次。** 一批保留來源定位、修改差異、未解疑點與驗證結果，歷史以檔案路徑引用，不把所有舊報告逐層塞進新 JSON。檢查點只保留目前進度、下一步與重要授權；既有歷史先留存，不為瘦身破壞復原證據。
- **進度分開計算。** 已對原譜核完但需更清晰原稿的歌曲，計入「本輪已掃描／等待補件」，不反覆當作未掃描。另報可用譜面的完成比例；註記精簡不算音符校對完成，不因文字變少改標題狀態。
- **衡量實際產出。** 每批記錄檢查首數、實際修改首數、轉待人工／補件首數、略過無新證據首數及耗時；只有可取得實測用量時才記 token，不編造節省百分比。若主要時間花在沒有變化的重查，先修正佇列與流程。

這些規則不會自動恢復已暫停的 automation，也不授權額外付費或重置券。後續清理舊註記仍須依 NAS 更新安全規則逐批進行。
