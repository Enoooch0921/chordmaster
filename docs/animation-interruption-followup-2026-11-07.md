# 回位、歌單導航與通知的中斷修正

接續使用者要求優化不自然、抖動與操作 bug 的動畫。本輪以既有動畫審查規則找可重現問題，再修改相關元件；使用本地合成資料驗證，未讀寫正式後端，未發佈。

| Before | After | Why |
| --- | --- | --- |
| 關閉音符鍵盤後，240ms 回位及上方留白收合沒有保留手動操作的中斷監聽，使用者捲動後仍會被動畫寫回 scrollTop | 回位與留白收合階段都接受 pointer／touch／wheel 中斷；舊動畫的更新與完成回呼另有 generation 保護 | 手動閱讀位置優先，不能讓結束中的動畫再把歌譜拉回去。`usePreviewKeyboardVisibility` |
| 直接移除鍵盤占位會把頁尾 scrollTop 強制壓回範圍，或令首行突然上移 | 中斷後僅暫留維持當前畫面所需的空間，捲回原可視範圍時移除；移除上方空間同步補償 scrollTop | 清理占位本身也不能造成第二次跳動。如果使用者停在臨時留白範圍內，保留該留白直到可無跳動地移除；卸載會清理 |
| 手動移動歌譜後更改減少動態偏好，effect 重建會忘記手動定位並再次移到選中小節 | 手動定位狀態以選中小節及 occurrence 保存；偏好或 callback 更新不重設，選取另一小節或重新操作鍵盤才恢復自動顯示 | 改變動態偏好不是重新選曲或選小節 |
| 歌單列表／詳情在滑入途中按 Tab 或切換減少動態，舊的 transform 仍跑完 | 明確完成當前 Motion 動畫；減少動態的 transform 時長為 0，正常減少動態進出保留 125ms opacity；以穩定 context 通知仍在退出的面板 | 僅改 transition 不會可靠停止已在運行、終點未變的動畫。保留導航方向、滾動記憶與退出 inert。`SetlistNavigator` |
| 帶操作按鈕的通知在鍵盤接手後仍滑入／淡入 | ToastCard 的進出透過既有鍵盤中斷機制立即完成，退出仍正常移除 | 操作目標取得鍵盤焦點時應保持穩定。`Toast` |
| 邀請遮罩展開途中改用鍵盤，仍需等完整展開與揭幕 | 將當前 journey 改成 instant，取消視覺動畫，但保留 ticket、導航與目的頁 ready 檢查 | 停止動態不等於取消邀請，也不應過早開放尚未就緒的頁面。`InvitationTransition` |

## 驗證

- 5 個相關測試檔共 47 項通過；捲動中斷補強後再執行其中 20 項捲動測試，全數通過，未重複加總測試數。
- 覆蓋：三種操作中斷關閉回位、過期 onUpdate／onComplete、上方留白移除補償、關閉與編輯中切換偏好、歌單進出中斷及快速反向、通知退出、邀請導航與目的頁就緒保護、既有 App 側欄行為。
- Chrome／WebKit，390、834、1440 px：以真實捲動容器與 wheel 操作在回位途中接手，等待動畫原定結束後 scrollTop 不再改變；上方留白清理後歌詞標記位置保持穩定；手動位置在切換減少動態前後一致。
- 同一矩陣確認歌單切換在 Tab／減少動態接手後位置歸零，退出面板移除；通知在 Tab 接手後完整顯示、停止位移，關閉後移除。
- Chrome／WebKit 邀請流程：展開中按 Tab 後無運行中的動畫；目的頁仍未 ready 時保留 inert 遮罩；ready 後解除遮罩，焦點移至目的頁標題。
- `npm run lint`、`npm run build`、`git diff --check` 通過。保留既有大型 chunk 警告，沒有宣稱本輪改善下載大小或測得實體 iPad FPS。
