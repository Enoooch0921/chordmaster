# 鼓手模式

版本：0.12.6（網頁版）

## 歌單與播放

從服事歌單下方開啟鼓手模式，載入當前歌單的歌曲順序、歌譜與 BPM。唯讀團員也能使用；演出調整不修改歌曲庫或共用歌單。歌單名稱、歌曲、順序與 Key 會隨來源歌單更新，保留鼓手目前選曲與本次手動設定。播放中固定原先的 BPM 與拍號，停止或換歌後才採用來源的新設定；被移除的播放中歌曲可繼續到手動停止，停止後選到仍存在的歌曲，不自動播放。點其他歌曲立即切歌並播放；點目前歌曲則切換播放／停止，載入中也可點按取消。未設定有效速度或拍號時先停止，填入 BPM 或使用 TAP 後再播放。

可使用加減鍵、原生輸入（最多一位小數）或 TAP 調整速度，再按還原箭頭回到歌曲原始 BPM。TAP 在 pointerdown 或控制器事件時間取樣，前幾下快速估計速度，連續點按逐步穩定，不以原本 BPM 慢慢追上。

每首歌可獨立調整節拍細分，預設每個 BPM 單位一次 Click；4/4 預設四分音符。數字拍點可循環調整重音，包含靜音、輕拍、一般與重音。拍號與複合拍分組決定 BPM 的計拍單位。

聲音設定提供 MultiTracks、Drive、Ableton Live Classic。三者使用原有取樣，音量與強弱以 gain 控制，不改音高；切換音色會重新啟動所選取樣。偏好與控制配置保存在此瀏覽器／裝置。

同帳號的個人區已接上即時更新通知；通知未送達時，前景每 5 秒檢查歌曲版本並更新歌單。團隊區維持每 15 秒備援檢查。未儲存修改、輸入編輯或同步寫入中會暫緩套用遠端資料，避免覆蓋本機修改；恢復連線或回到前景會重新檢查。一般樂譜演出模式與鼓手演出模式都持續接收更新，保留目前選曲；鼓手演出模式以固定播放時序保護 Click。啟動快取完成雲端驗證、未儲存變更的自動儲存及離線佇列送出，也不再等待退出演出模式。更新保留同一個畫面與譜面元件，不整頁重載或淡入；同一首歌的 Key／內容更新保留翻頁位置，頁數減少時只縮到仍存在的最後一頁。歌單增刪不重新置中捲動位置，也不打斷使用者正在進行的選曲捲動。此修正包含在 0.12.5。

## 裝置與演出配置

一般模式與演出模式的模式切換、MIDI／鍵盤入口集中在左側。大螢幕演出模式讓歌單在上、控制在下，右側維持完整 A4；多頁歌譜以點按翻頁，也可設定鍵盤或 MIDI 翻頁。直向演出模式隱藏樂譜。

手機橫向（寬不超過 1000px、高不超過 500px）使用節拍器與歌單兩欄，不顯示歌譜。拍點在上方，速度、加減與拍號在中間，播放／TAP／上下首在底部。還原鍵保留獨立 44px 空間，不與底部按鍵重疊。TAP 按下立即變色、下壓 1px，放開以 100ms 回彈；減少動態效果時只保留顏色回饋。

右側卡片高 88px，左上序號、右上拍號，速度置中、歌名在下。寬度低於 800px 採單欄，其餘採雙欄；長歌名省略並保留完整可存取名稱。此配置隱藏卡片內的細分按鈕，保留節拍器的細分選擇。切歌會依方向露出前一排／下一排，同時讓當前卡片保持可見。

手機歌單的鼓手入口與標題同列，回收 68px 固定高度。平板與寬螢幕（寬至少 600px、高至少 501px）的一般與演出模式採用拍點在上、速度與拍號在中、播放／TAP／上下首在下的順序；切歌鍵高 72px。速度下方設有固定 44px 的 BPM／還原列，避免點按範圍重疊。

## 鍵盤與 MIDI

開啟設定，選擇來源與裝置，依序點選要學習的動作，再按實體按鍵或鍵盤鍵。速度旋鈕需要相對值模式，依指示左右各轉一下；支援的相對值格式由學習流程辨識。儲存為自己的配置，重新開啟後可選用。

動作包含 TAP、播放／停止、速度加減、上一首／下一首、樂譜上一頁／下一頁；MIDI 額外保留速度旋鈕。輸入欄位、設定畫面與學習流程會阻擋演出快捷鍵，避免誤觸；翻譜不切換歌曲，也不重啟 Click。

Web MIDI 需要瀏覽器支援。此網頁發布不包含原生 iOS MIDI 橋接 App；不要將控制器接上 iPad 就視為已支援。實機控制器、供電、轉接器及瀏覽器支援需分別確認。硬體選擇與相對旋鈕說明見 [鼓手控制器與鍵盤](drummer-controller-guide.md)。

## 音訊與限制

0.12.3 修正 0.12.2 媒體 loop 交界可能停頓的回歸。Click 預先混合為 PCM 小節，交由 AudioBufferSourceNode 原生循環，音訊時鐘決定循環及畫面拍點；不以 JavaScript 計時器重啟每一小節。變更速度或音色時，新來源與舊來源在同一排程時間交接。獨立 HTML 媒體元素僅播放靜音工作階段支援，並不承接 Click 聲音，不能影響小節交界。

新使用者預設 Ableton Live Classic；已儲存的使用者音色仍保留。播放中換音色時舊聲音持續，選單顯示「準備音色…」，自動重試一次；載入失敗時靜默保留原音色並還原選項。每個啟動／載入請求設 8 秒期限，避免永久等待。平板原生選單若造成短暫中斷，仍記住選擇前的播放意圖。

Click 播放時，支援的瀏覽器設定 `navigator.audioSession.type = "playback"`，搭配靜音媒體輔助保留演出播放路徑。停止時暫停媒體輔助與 AudioContext，還原原先音訊類型並解除媒體控制鍵。MIDI／鍵盤預備不占用播放工作階段；TAP 純測速不啟動聲音。切換 App／分頁不主動停止 Click；回到畫面後恢復原生輸出並同步拍點，手動停止則保持停止。提供 Media Session 的播放、暫停、停止操作。背景或鎖屏是否持續出聲，仍受系統與瀏覽器限制，尚待實體 iPhone／iPad 驗證。螢幕喚醒鎖僅在支援時使用。

與其他 App 音樂同時播放的實驗功能已依使用者決定移除，包含選項、設定值與音訊切換分支。先前本機儲存的舊混音偏好會被忽略並清除；音色與音量偏好保留。

0.12.5 發布前完整測試包含 2169 項（192 檔），涵蓋 PCM WAV 拍點／細分／靜音、媒體時鐘與循環、換音色失敗保留、逾時、觸控選曲、手動停止與前背景恢復。舊 Web Audio 排程另有 30 分鐘模擬；此模擬不等同新版在實機背景播放 30 分鐘。內建瀏覽器分頁切換測試中 document.hidden 仍為 false，因此未把它列為真正背景實測。最初使用者平板的無聲／選曲不動仍需實機回歸確認。

## 縮放與寬螢幕排列修正（0.12.2）

移除 1439px 的排列上限，跨過 1440px 仍採拍點、速度與拍號、底部四鍵的順序；控制區最大寬 600px。一般與演出模式在 1366、1440、1518、1708、1920、2560px 的等效 CSS 寬度驗證了按鍵對齊、順序、還原鍵間距及無水平溢出；此為瀏覽器尺寸驗證，尚未實機操作 iPad 的頁面縮放。

## 觸控可靠性修正（0.12.2）

歌曲在 touch／pen 正常放開時直接選取，不依賴後續合成 click；保留捲動／取消判斷，避免同一觸控重複播放。滑鼠與鍵盤仍使用 click。

## 原生鍵盤與觸控定位修正（0.12.5）

保留電腦、手機與平板的原生 BPM 輸入。鼓手覆蓋層跟隨 VisualViewport 的可視高度與位置；手機／平板鍵盤彈出時暫時集中顯示速度輸入，避免拍點或歌單把數字推到鍵盤後面。鍵盤收起後於動畫結束期間重新校正，只重設已鎖定的文件捲動，不改歌單或樂譜的捲動位置；也處理 iPad 收鍵盤卻未發出 blur 的情況。

原生鍵盤觸控錯位參考 [WebKit 254861](https://bugs.webkit.org/show_bug.cgi?id=254861)。本機模擬 viewport 事件不等同實體 iPhone／iPad 測試。

## 切換音樂 App 後的音訊恢復（0.12.5）

回到前景時重新連接原生音訊輸出，檢查音訊時鐘是否前進；resume 卡住或時鐘凍結時重建 AudioContext，並保留已解碼的音色。恢復失敗會有限次自動重試，後續點按／按鍵也可在使用者操作期間重試。手動停止會取消恢復意圖。重新點歌／播放可建立新的原生輸出路徑。

無聲不能僅憑 AudioContext.running 或時鐘前進斷言已出聲，實體裝置與輸出仍需確認。參考 [WebKit 291892](https://bugs.webkit.org/show_bug.cgi?id=291892)。


## 聲畫同步與畫面卡頓（0.12.5）

聲音由原生 AudioBufferSourceNode 持續循環，畫面只透過 requestAnimationFrame 讀取當下拍點，兩者不互相等待。畫面漏幀後直接跟上當下拍點，不補播錯過的閃光，也不重啟 Click。拍點以實際 PCM 循環長度及取樣位置計算，避免理想 BPM 與小節取樣取整差異讓畫面在長時間播放後慢慢偏離聲音。瀏覽器提供 getOutputTimestamp 時，用音訊輸出時間戳校正畫面；不支援或回傳無效時間戳時退回音訊引擎時間。螢幕更新率與實際音訊輸出仍影響可見同步，尚未宣稱實機聲畫零誤差。系統暫停音訊或瀏覽器終止程序屬另一種中斷，由音訊恢復流程處理。


## 開啟 App 預載與音色音量校正（0.12.5）

App 掛載後以非阻塞方式開始下載三組音色的六個 WAV，使用 OfflineAudioContext 安靜解碼，不建立即時播放工作階段、不自動出聲。不支援離線解碼時先下載，首次播放才解碼。原始位元組及解碼後的 AudioBuffer 在同一頁面共用，切換音色、重開鼓手模式或重建播放 context 都能重用；失敗／逾時項目會退出快取，讓後續操作重試。實際播放仍需使用者點按啟動系統音訊；尚未預載完、首次離線或系統啟動音訊時，仍可能有等待。

以原始 Ableton Live Classic 的一般拍與重音各自為響度基準；保持音高、速度與原始 WAV 不變，解碼後只施加一次固定增益。以與原生 Click 相同的聲道算術平均、48 kHz、120 BPM 一般拍／重音各自的 8 秒點擊序列，使用 EBU R128 K 加權量測。Ableton 維持 0 dB；MultiTracks 一般拍 +1.3 dB、重音 +6.3 dB；Drive 一般拍及重音各 -5.5 dB。量測資料及尖峰檢查保存在本機驗證目錄；不同裝置、耳機與音色頻譜的主觀感受仍需試聽。


## 移除吉他手模式（0.12.5）

移除桌面與手機更多選單中的吉他手模式、切換狀態及依調性自動套用 Capo 的個人覆蓋層。啟動時清除舊版 `chordmaster.guitarist-mode.v1` 偏好。既有歌曲與歌單的明確 Capo 設定、個人 Capo 偏好及一般 Key／Capo 選擇器保留；樂譜標題下方依序呈現 Key、Capo、速度與拍號；Capo 大於 0 才顯示，0 或未設定時隱藏，預覽、演出與 PDF 一致使用這些設定。

## 切歌交接與手機控制間距（0.12.6）

切換至可播放的歌曲時直接在同一個原生音訊路徑交接，從新歌曲第一拍開始；不先停止、暫停 AudioContext 或釋放播放工作階段。切到未設定速度／拍號的歌曲，或再次點目前歌曲停止時，仍正常停止。新歌曲啟動尚未完成期間不以設定更新覆蓋該次啟動，完成後再套用最新速度調整。

手機歌單頁、手機橫向與直向演出模式不建立隱藏樂譜；使用者開啟樂譜頁籤或切換至會顯示樂譜的尺寸時，再載入目前歌曲。手機直向拍號與拍點保留間距，還原速度使用獨立的 44px 控制列，不伸入播放按鈕範圍。實體裝置的切歌手感仍需確認。
