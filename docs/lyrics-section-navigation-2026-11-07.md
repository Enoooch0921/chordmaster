# 歌詞段落導覽

使用者在手機和平板試用後，要求移除歌詞底部的上一頁／下一頁，將兩步操作的段落下拉選單改成一次點按的 V1、V2 等段落標籤，並抬高控制列避開手機底部多工手勢區。另要求明確的選取狀態與動畫回饋。

## 實作

- `LyricsSectionNavigation` 沿用 `songMapDisplayCode`，產生 V1、V2、Pc、C、B 等既有曲序縮寫。自訂標籤仍保留完整 accessible name 與 title；過長文字只在視覺上省略。
- `AdaptiveLyricsReader` 點按段落後記錄該 block ID 與來源第 0 行，跳到該段的第一頁。同頁跳段也會更新選取狀態。量測重排時若該來源 anchor 仍有效，優先保留，不再一律覆寫成該頁第一段。
- 左右翻頁依然以頁為單位，跨歌邊界仍依序切歌或返回前曲最後頁。桌面也支援歌詞區左右半邊點按，避免移除箭頭後無法以滑鼠閱讀單一長段落的續頁。
- 段落標籤至少 44×44px，單列橫向捲動。選取標籤會自動捲至可見位置，只調整標籤列，不捲動 document 或歌詞畫布。演出滑動辨識會避開整個 footer，包含標籤間的空隙。
- footer 留 `16px + env(safe-area-inset-bottom)` 底部空間；專注閱讀移除外層重複 inset。演出 overlay 原本就有安全區內距，其 footer 只增加 16px。
- 回饋定位為常用控制的 Feedback／State indication：重用 `MeasuredSlidingSelection`，以 160ms、既有 `UI_EASE_OUT`、transform-only 移動選取底色；按壓沿用現有 100／160ms tokens。初次呈現不進場，快速連點可從當前視覺位置重新定位。鍵盤選取即時生效；減少動態效果時不滑動。歌詞不使用切換動畫。

## 驗證

10 個相關測試檔、144 項測試通過，包含同頁選取、一次跳段、來源 anchor、調字與旋轉、跨歌、演出鍵盤、只讀及明確換頁設定。TypeScript 與 production build 通過。

Chromium／WebKit 檢查 320×568、390×844、844×390、834×1194、1024×768、1366×1024，逐頁比對〈點燃〉19 個來源行各出現一次，無水平或垂直溢出。各尺寸的段落按鈕均至少 44×44px、距容器底部至少 16px；未設定偏好時直向手機為 22px，其餘矩陣使用 24px，390×844 仍為兩頁。

兩引擎皆檢查 160ms 選取動畫、減少動態無位移、同頁選取、專注／列印往返與 13 段壓力資料的自動可見捲動。以 34px 底部 inset 的模擬 CSS 檢查，按鈕底緣保留 50px 距離。這是安全區版面模擬，非實體 iOS Home indicator 證據。

Chromium 另用 CDP 觸控輸入驗證手機／平板左右點按與滑動、跨歌、直向手勢、雙指、選字、演出翻頁、footer 空隙不接管滑動，以及原生橫向捲動段落列不翻歌詞頁。雙指案例後恢復測試頁的 page scale，避免以縮放後的座標誤判點按。未強制穿透被擋住的控制。

Impeccable detector 的 6 個結果皆為既有字體與局部文字尺寸，新增導覽沒有新提示；沿用原本設計 tokens，沒有更新全域設計系統。
