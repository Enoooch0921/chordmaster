# ChordMaster 0.12.28 — 2026-11-07

這次針對「連續快速往後翻到新歌會延遲，但等候後或往前返回較順」的情況。0.12.27 每次翻頁都會重新等待 500ms，初始又只預備後面兩首；快速連翻時會持續延後預載，超過範圍就必須在按下時才建立新譜面。

現在先讓當前譜面有呈現機會，再於閒置時逐首準備後續曲目，不再每次翻頁或每完成一首都重新等待半秒。下一首優先，一般短歌單可以準備整份。即使翻得比預載快，剛看過的譜面也會保留供返回。

保留量受兩個條件限制：最多八個曲目，額外預載使用 512 個來源小節的預算；當前、下一首與上一首優先，即使個別長譜超出額外預算也會保留。這是來源內容大小的估算，不是裝置記憶體的精確上限。超出保留範圍或尚未完成準備的曲目仍可能需要即時建立。手寫接觸期間不執行背景準備，離筆後繼續等候空檔。

WebKit iPad 模擬視窗使用整個 App 的八曲合成歌單，以約 100ms 間隔連續前進七首、再返回七首。舊版前進有五次沒有預備好的譜面；新版前後十四次都沿用原有節點。另以八首各 64 小節的長譜，以及進入演出約 100ms 後就開始快速翻歌，兩組各十四次也都沿用已預備的節點。這些是本機瀏覽器驗證，不代表實際 iPad 的總呈現時間。

回歸測試涵蓋短於半秒的連續輸入仍可持續準備、無法執行閒置回呼時保留剛看過的譜面、曲目與小節預算、手寫暫停，以及原有分頁、橫直向、筆記與踏板行為。

## 在 iPad 更新

退出演出模式，點「立即更新」，確認版本為 **v0.12.28**。可在進入演出後直接快速往後翻過三首以上，再往前返回，測試是否還會遇到按下才開始載入的停頓。
