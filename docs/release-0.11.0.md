- 統一歌曲編輯、歌單編輯、歌曲排序、加入／移出歌曲、歌單與專案新增／複製／移動／歸檔／刪除的撤銷與重做。此裝置每個帳號與歌曲庫保留最近 50 步；一次連續拖曳只算一步。

本次發布不包含另一批尚未提交的歌詞 A4 排版與逐曲校對修改。

## 資料庫與發布順序

正式後端為教會 NAS：`https://supabase.living-water.familyds.com`。只套用 `20261027173400_workspace_history.sql`，不推送歷史 migration 或轉錄資料。

先備份受影響函式、ACL、trigger 與預設權限，再於 NAS 交易回滾試跑、套用及驗證，最後發布前端。DDL 交易內核對原有歌曲、專案、歌單、項目、團隊成員、共享成員、指派與個人 Capo 的完整列雜湊。私有備份與執行紀錄保存在儲存庫外的私人備份目錄，不提交認證資料或會員 token。

每個新 RPC／helper 都明確撤銷匿名執行權。保留 NAS 既有跨 schema 的預設函式權限，避免影響其他 Supabase 服務日後的 migration；既有 default-privilege probe 所指出的全域預設議題不在本次變更範圍。

GitHub Actions 對發布 commit 執行型別檢查、測試及建置後部署 GitHub Pages。前端回滾時保留私有刪除備份與恢復 RPC，避免丟失復原能力。

## 發布前驗證

隔離發布版本通過 140 個測試檔／1,380 項測試、TypeScript 與正式建置。暫存 PostgreSQL 通過 103 個撤銷功能、117 個團隊管理及 187 個歌曲庫權限 SQL statement。

NAS 已完成備份、回滾試跑、原有資料列雜湊核對與套用；七個新 RPC／helper 存在、匿名不可執行、私有備份不可讀取。另以交易內合成資料驗證歌曲排序／復原、專案刪除／恢復、歌單刪除／恢復及保護式欄位更新，全部回滾且無殘留測試列。
