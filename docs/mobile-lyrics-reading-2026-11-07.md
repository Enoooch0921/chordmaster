# 手機歌詞閱讀與觸控翻頁

使用者要求回收手機歌詞模式頂部空間、減少〈點燃〉等歌曲的換頁，並在手機和平板支援左右滑動、左右點按。確認後採用稍小的手機預設字級，保留閱讀下限與手動調整。

## 行為

- 閱讀時將歌名／選曲、列印、閱讀設定、允許的編輯與專注閱讀合併為一列。手機的調性、Capo 等工具列在鎖定閱讀時收起，歌詞模式切換仍在主標頭。列印模式保留閱讀／列印切換。
- 尚未儲存偏好的手機（視窗寬度不超過 639px）以 22px 開始，其他裝置以 24px 開始。既有儲存值優先。字級仍以 2px 調整，範圍為 20–40px；換歌、翻頁、旋轉與專注閱讀不會自動縮字。
- 分頁先嘗試保留完整段落；只有能減少頁數時，才採用利用剩餘空間的分段方案。同頁數依序優先較少段落接續、較少折行、較均衡欄寬。原始句子／雙語配對與明確換頁設定仍完整保留。
- 歌詞內容區支援向左滑往後、向右滑往前；手機／平板也可點左半邊往前、右半邊往後。跨歌沿用既有行為：往前一首進入最後一頁。既有底部按鈕與鍵盤翻頁繼續可用。
- 重用演出模式的滑動辨識，演出時只由既有外層處理手勢。滑動在放手時翻一次並擋掉相容 click；直向捲動、雙指操作、取消與選字不觸發翻頁。普通閱讀的長按與起手已有選取文字的點按也不翻頁。
- WebKit 原生下拉選單明確設定 44px 高度，避免僅設定 min-height 時仍只有 20–31px 的實際點按範圍。

## 〈點燃〉前後對照

以 NAS access helper 唯讀取得的既有〈點燃〉快照，在離線 App fixture 中驗證。沒有生產資料寫入，fixture 未載入 Supabase 憑證。手機測試頁包含本地模式提示，前後條件一致。

| 390×844 | 調整前 | 調整後 |
| --- | ---: | ---: |
| 字級 | 24px | 22px |
| 主工具列高度 | 119px | 65px |
| 閱讀工具列＋獨立歌名區 | 134px | 73px（含內容頂部留白） |
| 歌詞畫布高度 | 480px | 595px |
| 頁數 | 3 | 2 |

調整後第一頁包含 Verse 1、Verse 2 與完整 Chorus；第二頁為 Bridge。全曲 19 個來源行都出現一次且內容與既有顯示處理後的來源一致。

## 驗證

Chromium 與 WebKit 皆驗證以下尺寸、淺／深色、完整逐頁來源涵蓋、沒有欄位或頁面溢出、所有閱讀工具列及頁尾控制至少 44px 高。此矩陣在手機手動調字後沿用同一份 22px 偏好；另外 Chromium 觸控流程也驗證重新載入平板時，未存偏好會以 24px 顯示。

| 視窗 | 〈點燃〉頁數（兩引擎一致） |
| --- | ---: |
| 320×568 | 4 |
| 390×844 | 2 |
| 430×932 | 2 |
| 844×390 | 4 |
| 834×1194 | 1 |
| 1024×768 | 1 |
| 1366×1024 | 1 |

兩引擎亦完成設定開合、調字、專注閱讀進出及列印／閱讀切換。Chromium 使用瀏覽器觸控 API 與 CDP 觸控輸入驗證左右點按、雙向滑動、直向手勢、雙指、選字、跨歌邊界與演出模式沒有重複翻頁。WebKit 使用瀏覽器觸控 API 驗證點按，並以合成 touch 事件驗證雙向滑動、垂直手勢不取消原生捲動與雙指取消。這些是模擬器／瀏覽器證據，未進行實體 iPhone、iPad 或 Android 測試。

自動檢查：15 個相關測試檔案、210 個測試通過；TypeScript 與正式 web build 通過。Build 保留既有大型 chunk 提示。Impeccable detector 掃描 68 個提示，其中改動行只有一個 19px 歌名選單 advisory，沿用原有歌名尺寸並記錄於局部 surface brief；其餘位於未變動的既有程式。沒有更動全域設計 tokens。
