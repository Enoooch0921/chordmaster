# 手機歌曲／歌單切換回饋

使用者確認範圍為手機側欄上方「歌曲／歌單」兩個按鈕。保留原有 160ms 選取底色位移及 125ms 內容淡入，修正切換分類時被遮住的譜面反覆建立，造成主執行緒忙碌、動畫可見畫面不穩定的問題。

`CoveredPreview` 在手機側欄開啟期間保留上一次已顯示的譜面及閱讀區，不隨分類切換重建；外部 inert 邊界立即生效，避免背景內容被操作。側欄關閉時顯示最新內容及事件處理函式。帳號、曲庫、所選歌曲／歌單或歌詞模式改變時解除保留，不能沿用另一個範圍的內容。側欄蓋住預覽時也暫停歌單預覽捲動定位，關閉後依目前選曲恢復。

兩個分類按鈕補上 touch-manipulation，保留點按、鍵盤及減少動態效果的原有邏輯。未加入動畫等待時間；選取歌曲後的側欄收起行為未更改。

## 驗證

- 7 個相關測試檔／57 項通過，含三次雙向分類切換均觸發淡入、背景譜面不重畫、關閉後顯示最新內容、事件處理函式更新，以及帳號／曲庫／歌曲隔離。
- TypeScript 檢查、正式 build、`git diff --check` 通過；保留既有大型 chunk 提示。
- 相同本機開發 fixture、3 首合成歌曲、390×844、Chromium CDP 觸控，六次切換均呼叫一次 125ms 淡入且沒有中途取消。第一個分類切換畫面原為 193.0–531.4ms，修正後為 80.2–175.3ms。
- WebKit 手機模擬以原生 tap 驗證五次雙向切換、搜尋輸入後切換、關閉／重新開啟與減少動態效果：每次切換均產生一次 125ms 淡入；關閉後從保留的歌單譜面更新為目前歌曲，輸入模式正常回到 pointer。首次滑鼠模擬曾遇到側欄動畫未落到終點；重新載入後以原生觸控開啟及再次開啟皆通過，未將這個自動化異常當作產品修復成果。

這些數字含開發模式及量測開銷，不是實體 iPhone／Android 的 FPS 或 INP 承諾。證據在 `output/playwright/mobile-tabs-20261106/`。本次修改與先前的固定譜面／觸點翻頁回饋都保留於本機，尚未發佈。
