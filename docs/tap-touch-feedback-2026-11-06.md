# 鼓手模式 TAP／播放觸控修正

## 重現與修正

Chrome 手機觸控測試重現：播放鍵按住 180ms 仍顯示「播放」、未啟動音訊，因為原先只在放開的 click 執行。TAP 已在 pointerdown 計拍，但回饋標記 50ms 後消失；觸控瀏覽器未必提供 CSS `:active`，按住時便失去回饋。

兩個控制現在於主要指標按下時執行，直接設定按壓顏色並保持到放開，不縮放或回彈。使用指標捕獲及 ID 比對處理移出、取消和解除捕獲；消耗後續 click，避免重複計拍或播放後立即停止。鍵盤長按不重複執行，獨立輔助技術 click 仍可操作。按鈕及子元素禁止選字／觸控 callout，contextmenu 取消預設行為；BPM 欄位等內容保留選字。

變更限於 `DrummerMode.tsx`、`DrummerMode.css`、相關測試及規範文件。沒有修改節拍計算、音訊引擎、音色、歌曲資料或後端。

## 驗證與界線

- 6 個相關測試檔共 140 項通過；測試查詢型別修正後，60 項元件測試再次通過。TypeScript 檢查與正式建置通過；建置保留既有大型 chunk 提示。
- Chrome 使用 CDP 真實觸控事件；WebKit 使用真實滑鼠長按與額外 touchscreen.tap，並非實體 iPhone。
- 390×844、844×390、834×1194：TAP 長按 700ms 只計一次且持續亮色；播放／停止在放開前更新；放開不重複切換；BPM 可選字；深色、減少動態效果與鍵盤回饋正常。
- contextmenu 取消以事件驗證，`user-select: none` 以按鈕／子元素計算樣式與選取結果驗證。實體 iOS 系統 callout 尚未驗證。
- 源碼設計偵測有 30 項既有字型／字級／色彩提示，本次修改行沒有提示。人工檢查按壓畫面與事件生命週期，範圍內無阻擋問題；結論：可交付本機變更。

本機證據：`output/playwright/tap-response-20261106/` 的 before/after JSON、兩組 verification JSON 及畫面。來源為 `tmp/drummer-mode-preview/` 的真實元件與合成歌曲，沒有讀取正式資料。腳本在 `tmp/tap-response-20261106/`。畫面是本機驗證截圖，不是產品素材。

音訊探針記錄的是 AudioBufferSourceNode.start 呼叫時間，不是喇叭實際出聲；單次冷啟動樣本不能當作硬體延遲承諾。本次移除等待放開的操作延遲，未宣稱首次音訊初始化為零延遲。尚未部署。
